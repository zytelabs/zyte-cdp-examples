# Contributing

Contributions should add a runnable example, fix a demonstrated problem, or clarify behavior specific to Zyte Browser CDP.

## New examples

Before adding a client, confirm that it can:

- Authenticate `/json/version` discovery, including cross-host redirects.
- Add the same authorization header to the WebSocket handshake.
- Attach to the existing default browser context.
- End the remote browser by sending `Browser.close`.
- Read credentials from `ZYTE_API_KEY` without logging them.

Keep examples independent and small. Include a README with prerequisites, install commands, the exact run command, expected behavior, and any files generated by the example. Do not require a local Chrome installation.

Use public demonstration sites and avoid workflows that submit real credentials, modify third-party data, or collect personal data.

## Checks

Run the checks relevant to the directories you changed. The CI workflow is the source of truth for supported versions and commands.

Live tests consume a paid browser session, so push and pull-request CI only compiles and checks source. Maintainers can run the `Live CDP smoke test` workflow manually after adding `ZYTE_API_KEY` as a repository secret. If you run an example with a real key, never include the key, authorization header, WebSocket URL, cookies, screenshots, traces, or HAR files in a commit or issue.

## Pull requests

Explain what the example teaches and why an existing example does not already cover it. Include offline test results. If you performed a live test, say which example ran and whether it completed, but redact all credentials and session URLs.
